Azure Content Safety — threshold & severity reference

A complete visual guide to how severity scores map to threshold settings across all four harm categories. Use this to choose the right threshold for your application.

azure.ai/contentsafety  ·  SDK: azure-ai-contentsafety
Core concept

The API returns a severity score per category. Your threshold determines what gets blocked:

content is BLOCKED if: severity_score ≥ threshold

Lower threshold = stricter filtering  |  Higher threshold = more permissive

Severity scores
0 Safe
No harmful content detected. Neutral, benign, or informational text.
"People walked in the park on Sunday."
2 Low
Mildly problematic or ambiguous content. Some negative framing, but not overtly harmful.
"Some people resent immigrants for taking jobs."
4 Medium
Clearly harmful or explicit content. Derogatory language, graphic descriptions, harmful intent visible.
"He grabbed the knife and stabbed him repeatedly."
6 High
Extreme or targeted harmful content. Step-by-step instructions, graphic detail, targeted threats.
"Detailed instructions to cause mass casualties…"
i The API returns only 0, 2, 4, or 6 — odd scores (1, 3, 5, 7) are never returned. However, thresholds 1–7 can be used in your configuration. Setting threshold = 1 is effectively the same as threshold = 2 (both block scores ≥ 2), since score 1 never occurs. Odd thresholds give you finer logical control in code without changing API output behavior.
Harm categories
Hate
Prejudice, slurs, dehumanization, or discrimination targeting groups by race, religion, gender, nationality, or other identity attributes.
Sexual
Explicit sexual content, graphic descriptions of sexual acts, inappropriate content involving minors, or non-consensual scenarios.
Violence
Physical harm, graphic brutality, threats against specific persons, instructions for causing bodily injury, or glorification of violence.
Self-harm
Suicide methods, self-injury encouragement, eating disorder facilitation, or content that promotes or instructs self-destructive behavior.

Threshold quick-reference
Threshold  ·  What it blocks  ·  Notes
0 Blocks all Flags every response including safe content. Only useful for testing or absolute zero-tolerance pipelines. Expect very high false-positive rate.
1 Blocks all Identical effect to threshold=0 since the API never returns score=1. Safe to use as a semantic alias for "block everything."
2 Blocks low+ Catches mild or ambiguous content. Best for children's platforms, educational tools, or highly regulated environments. Moderate false-positive rate on edgy-but-legitimate text.
3 Blocks low+ Same effect as threshold=2. Semantically useful to distinguish "designed to block low" from threshold=2 in code comments.
4 Blocks medium+ Most common production default. Allows general discussion (news, debate, fiction) while blocking clearly harmful content. Best precision/recall balance for general-purpose apps.
5 Blocks medium+ Same effect as threshold=4. Use as a semantic marker if your code distinguishes "strict medium" from "loose medium."
6 Blocks high only Only extreme content is flagged. Suitable for adult platforms, security research tools, legal/forensic analysis. Lowest false-positive rate; some harmful content passes.
7 Blocks nothing All content passes — even score=6 (high) is allowed. Effectively disables filtering. Use only for logging-only modes where you capture scores without blocking.
Recommended configurations
threshold = 2 Strict — block low and above
Zero tolerance for potentially sensitive content. Flags anything that could be interpreted as mild hate, innuendo, or uncomfortable themes. High false-positive rate in general conversation.

Best for

Children's apps K–12 education Parental controls Regulated healthcare
threshold = 4 Balanced — block medium and above
Allows discussion of sensitive topics in a news, research, or debate context while reliably catching clearly harmful content. The recommended starting point for most production apps.

Best for

General chat apps Enterprise tools Customer support bots News summarizers
threshold = 6 Permissive — block high only
Only the most extreme content is blocked. Allows explicit discussion of violence, hate, and adult themes for research or specialized platforms. Requires additional moderation layers.

Best for

Security research Adult platforms Forensic analysis Content moderation tools
threshold = 7 Disabled — logging only
Blocks nothing. Use to capture severity scores for analytics, model evaluation, or audit logging without affecting the user experience. Always pair with human review or alerting.

Best for

Audit pipelines Severity logging Model evaluation A/B threshold testing
